Docker Desktop no Windows 11

Para que serve o Docker, o que o Compose resolve e o passo a passo para instalar e configurar. No fim, você sobe banco e serviços do curso com um comando, sem instalar nada disso direto no Windows.

Para que serve o Docker

O Docker roda programas dentro de containers: caixas isoladas que já trazem o programa e tudo o que ele precisa para funcionar. Um PostgreSQL num container roda igual no seu notebook, no do colega e no servidor.

ImagemO molde pronto para baixar, como postgres:16. Fica no Docker Hub.
ContainerA imagem rodando. Você liga, desliga e apaga sem afetar o Windows.
VolumePasta onde o container guarda dados que precisam sobreviver, como as tabelas do banco.
PortaA ponte entre o container e sua máquina. 5432:5432 deixa o banco acessível em localhost:5432.

Como as peças se encaixam no Windows

Containers do projeto

Lido de baixo para cima: o Windows roda o WSL 2, o WSL 2 roda o Docker, e o Docker roda os containers.

E o Docker Compose?

Um projeto real precisa de vários containers juntos: banco, tela do banco, às vezes cache ou fila. O Compose descreve todos num arquivo docker-compose.yml, que fica no Git junto com o código. Um comando sobe tudo e outro derruba tudo.

docker-compose.yml
services:
  db:
    image: postgres:16
    environment:
      POSTGRES_USER: curso
      POSTGRES_PASSWORD: curso
      POSTGRES_DB: app
    ports:
      - "5432:5432"
    volumes:
      - dados-db:/var/lib/postgresql/data

  adminer:
    image: adminer
    ports:
      - "8080:8080"
    depends_on:
      - db

volumes:
  dados-db:

Com esse arquivo na pasta, docker compose up -d sobe o PostgreSQL em localhost:5432 e a tela do banco em localhost:8080. Sua API em Go conecta com usuário curso, senha curso, banco app.

Antes de instalar

  • Windows 11 de 64 bits, Home ou Pro, atualizado.
  • 8 GB de RAM ou mais. Com 4 GB funciona, mas fica lento.
  • Virtualização habilitada. Confira em Gerenciador de Tarefas (Ctrl+Shift+Esc) > Desempenho > CPU: a linha Virtualização deve dizer Habilitado.
Virtualização desabilitada? Ela é ligada na BIOS. Reinicie o PC, entre na BIOS (geralmente F2, F10 ou Del durante o boot) e ative Intel VT-x (Intel) ou SVM Mode (AMD). O nome muda por fabricante; pesquise "ativar virtualização" + o modelo do seu notebook.

Instalação passo a passo

  1. Instale o WSL 2

    Abra o Terminal como administrador (botão direito no menu Iniciar > Terminal (Administrador)) e rode:

    PowerShell (admin)
    wsl --install

    Reinicie o computador. Na volta, ele pode abrir uma janela do Ubuntu pedindo usuário e senha do Linux: escolha qualquer um e anote. Se o WSL já estava instalado, rode wsl --update.

  2. Instale o Docker Desktop

    Pelo terminal:

    PowerShell
    winget install -e --id Docker.DockerDesktop

    Ou baixe o instalador em docker.com/products/docker-desktop. Na tela de configuração, deixe marcado Use WSL 2 instead of Hyper-V.

  3. Reinicie ou saia da conta

    O instalador pede para fazer logout ou reiniciar. Faça, senão o Docker não enxerga o WSL.

  4. Abra o Docker Desktop

    Aceite os termos. O login com conta Docker é opcional: clique em Skip se não quiser criar. Espere o rodapé da janela mostrar Engine running em verde.

  5. Teste no terminal

    Abra um terminal novo (sem ser admin) e rode os três comandos:

    PowerShell
    docker --version
docker compose version
docker run hello-world

    O último deve imprimir Hello from Docker!. Se apareceu, está tudo funcionando.

Configurações recomendadas

Abra o Docker Desktop e clique na engrenagem (Settings) no topo.

  • General > Use the WSL 2 based engine: deixe marcado.
  • General > Start Docker Desktop when you sign in: desmarque se o PC tem pouca memória. Aí você abre o Docker só na hora de estudar.
  • Resources > WSL integration: se você programa dentro do Ubuntu (WSL), ative a chave do Ubuntu para usar docker por lá também.

Limitando a memória

O Docker pode usar metade da RAM do PC (aparece como Vmmem no Gerenciador de Tarefas). Para limitar, crie o arquivo .wslconfig na sua pasta de usuário (C:\Users\SeuNome) com o conteúdo abaixo e rode wsl --shutdown.

.wslconfig
[wsl2]
memory=4GB
processors=2

Para um PC com 8 GB, 4 GB para o Docker é um bom equilíbrio. Com 16 GB, pode usar 6 ou 8.

Comandos do dia a dia

Rode na pasta onde está o docker-compose.yml.

docker compose up -dSobe os serviços em segundo plano
docker compose psMostra o que está rodando e as portas
docker compose logs -f dbAcompanha o log do banco (Ctrl+C para sair)
docker compose downDesliga tudo e mantém os dados
docker compose down -vDesliga e apaga os dados do banco
docker system pruneLimpa containers e imagens que não estão em uso

Se o projeto tiver Makefile, é ainda mais curto: make up e make down.

Deu erro?

Virtualization support not detectedA virtualização está desligada na BIOS. Veja "Antes de instalar".
WSL 2 installation is incomplete / WSL needs updatingRode wsl --update no terminal e abra o Docker Desktop de novo.
Docker Desktop parado em "Starting the Docker Engine..."Feche o Docker Desktop, rode wsl --shutdown e abra de novo. Se persistir, reinicie o PC.
'docker' não é reconhecido como um comandoFeche e abra o terminal (e o VS Code inteiro). O Docker Desktop precisa estar aberto.
error during connect ... pipe/docker_engineO Docker Desktop está fechado. Abra e espere o "Engine running".
Bind for 0.0.0.0:5432 failed: port is already allocatedOutro programa usa a porta, quase sempre um PostgreSQL instalado no Windows. Pare esse serviço ou troque para "5433:5432" no compose.
PC lento, Vmmem usando muita memóriaCrie o .wslconfig da seção de configurações e rode docker compose down quando não estiver usando.
